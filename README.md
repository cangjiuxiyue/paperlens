# PaperLens · 学术文献智能检索与推荐系统

一个从零实现的信息检索系统：**手写 BM25、TF-IDF 向量空间模型、多信号混合排序**，不依赖任何 NLP / 向量库，自带 50 篇论文数据集与 19 条带相关性标注的评测查询，可在网页上实时对比三种排序策略的 NDCG / MRR。

> 这不是一个调包 Demo。检索的核心逻辑（分词、倒排索引、打分、融合、评测）全部在 `src/core/` 里手写，每一行都能讲清楚为什么这么写。

## 4. 核心设计

### 4.1 分词：为什么不直接用现成的库

- **英文**：小写化 → 去停用词 → 轻量词干化（`ranking / ranked / ranks → rank`，`embeddings → embed`）
- **中文**：按字切 bigram（`注意力机制 → 注意 / 意力 / 力机 / 机制`）

bigram 不需要词典，对未登录词天然鲁棒，代价是索引膨胀约 2 倍。在 50 篇语料上这个代价可以忽略，所以我选择了实现成本最低的方案——**这是个可以主动讲出来的取舍**。

### 4.2 BM25：两个参数到底在控制什么

```
score(q, d) = Σ_t IDF(t) · ( tf · (k1+1) ) / ( tf + k1 · (1 - b + b · |d| / avgdl) )
```

- `k1 = 1.2`：控制**词频饱和**。一个词出现 10 次不该比出现 1 次重要 10 倍，分母里的 `tf` 负责把它压平。
- `b = 0.75`：控制**长度归一化**。长文档天然容易命中词项，必须打折，否则综述类文章永远排第一。
- `IDF = log(1 + (N - df + 0.5) / (df + 0.5))`：加 1 的平滑形式保证 IDF 恒为正，避免极高频词拿到负分把总分拉低。
- **字段加权**：标题 ×3、关键词 ×2、摘要 ×1。这是检索系统里性价比最高的精度提升手段。

### 4.3 混合排序：把异构信号塞进一个可解释的框架

```
final = 0.70·BM25 + 0.20·余弦 + 0.05·引用 + 0.05·时效 + 0.05·短语命中
```

每一项先归一化到 `[0,1]` 再加权，所以**每条结果的分数都能拆开看**（前端卡片底部的 5 段小条就是这个拆解）。这比端到端黑盒模型更适合做产品解释，也方便按业务加信号。

权重不是拍脑袋定的，是 `npm run tune` 在标注集上网格搜索出来的。

### 4.4 评测：为什么必须有指标

没有指标的检索系统只能靠「感觉还行」。`evaluate.ts` 手写了四个指标：

| 指标 | 回答什么问题 |
| --- | --- |
| P@5 | 前 5 条里有多少条真的相关（分母固定为 5，避免结果少反而精度高的假象） |
| R@5 | 前 5 条覆盖了全部相关文档的多少 |
| NDCG@10 | 考虑**相关性等级**和**位置折损**，最贴近真实排序质量 |
| MRR | 第一条相关结果的倒数排名，衡量用户是否一眼看到答案 |

## 5. 实验结论（这部分比代码更重要）

19 条查询、10 条截断的评测结果：

| 指标 | BM25 | 向量空间 | 混合排序 |
| --- | --- | --- | --- |
| P@5 | 0.5368 | 0.5368 | 0.5368 |
| R@5 | 0.7254 | 0.7254 | 0.7254 |
| **NDCG@10** | **0.9062** | 0.8991 | 0.9040 |
| **MRR** | **1.0000** | 0.9737 | 1.0000 |

**结论一：BM25 是最强基线，混合排序没能超过它（-0.24%）。**

这和 BEIR 基准的结论一致：语料规模小（50 篇）、查询与标题词汇高度重叠时，词项匹配已经接近最优，额外信号只会稀释它。我没有为了让数字好看去调评测集——**负结果也是结果**。

**结论二：三种模式的召回集合完全一致。**

P@5 / R@5 三列相同，说明差异只发生在**排序顺序**上。这正好说明为什么需要 NDCG 和 MRR：它们才是排序模型真正要优化的目标。

**结论三：向量空间模型在查询词稀疏时更稳。**

`pretrained word embeddings` 这条查询上，向量模型 0.988，BM25 只有 0.838。原因是余弦相似度会被稀有词主导，不会被长文档的绝对词频稀释。

**结论四：引用与时效先验是噪声。**

网格搜索的最优解会把这两项压到接近 0。因为高被引论文普遍偏老，`Transformer`（12 万引用）会把 `vLLM` 这类真正相关的论文挤下去——**相关性和影响力是两个不同的东西**。

**所以产品的默认策略是「默认 BM25，混合排序保留为可解释的多信号框架」。**

## 6. 如果继续做，下一步是什么

1. **真正的语义检索**：接入 sentence-transformers 生成句向量，用 HNSW 建索引。这是唯一能突破「词汇重叠」天花板的方向，也是本实验结论直接指向的下一步。
2. **伪相关反馈（Rocchio / PRF）**：用初次检索的 top-k 文档扩充查询，成本极低，对短查询通常有效。
3. **评测集扩充**：19 条查询的置信区间很宽，至少要 100+ 条并做 k 折交叉验证，否则调参必然过拟合（`tune.ts` 里已经写了这个风险提示）。
4. **性能**：目前向量检索是 O(N) 全量点积，50 篇无所谓，5 万篇就必须上 ANN 索引。

## 7. 面试可能被追问的问题

**Q：为什么不用 Elasticsearch / FAISS？**
A：因为面试要考察的是我知不知道里面发生了什么。手写一遍之后，我知道 BM25 的 `b` 为什么是 0.75，知道 HNSW 解决的是哪一步的复杂度问题——这时候再用现成组件，我能说清楚在什么场景下该调什么参数。

**Q：你的系统比 BM25 差，那这个项目有什么价值？**
A：价值在于我**知道它差、知道为什么差、也知道怎么改**。我做了对照实验，找到了原因（语料小 + 词汇重叠 + 引用先验有偏），并且明确了下一步该引入稠密向量。这比一个说不清原理、只展示漂亮截图的 Demo 有价值。

**Q：NDCG 怎么算的？为什么不用准确率？**
A：NDCG = DCG / IDCG，DCG 是 `Σ(2^rel - 1) / log2(i+2)`，位置越靠后折损越大。检索是排序问题不是分类问题，用准确率会丢掉「排在第 1 位还是第 9 位」这个关键区别。

**Q：怎么保证代码质量？**
A：21 个单元测试覆盖分词、BM25 排序、指标计算；`evaluate.ts` 的 NDCG 用手算值做了断言校验（`test/evaluate.test.ts`）；所有模块按「索引 / 打分 / 融合 / 评测」分层，新增一种排序策略只需要在 `engine.ts` 里加一个分支。
